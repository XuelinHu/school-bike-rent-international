国际化学生单车租赁管理软件软件设计说明书

1 引言

国际化学生单车租赁管理软件V1.0 是面向高校学生、留学生、管理员和运维人员的校园单车租赁管理软件。系统采用 H5 前端、Node.js 后端和 MySQL 数据库，围绕车辆查询、租赁、归还、订单、维护、公告、后台统计和中英文国际化形成完整业务链路。本文用于说明软件需求、模块结构、总体设计、详细设计、数据库设计、接口设计、运行部署、安全控制和测试验证情况。

2 用户需求分析

2.1 角色需求

  1. 学生用户需求：学生需要通过 H5 页面完成注册登录、查看车辆、筛选可租车辆、查看车辆详情、发起租赁、归还结算、查看当前订单、查看历史订单、维护个人资料、浏览公告以及切换中文和英文界面。
  2. 管理员需求：管理员需要通过后台查看业务统计，维护用户、车辆、站点、订单、维护记录和公告数据，掌握车辆投放、租赁状态、收入统计和公告发布情况。
  3. 运维人员需求：运维人员需要查看维护记录、登记维护内容、将故障车辆置为维护中，并在维护完成后恢复车辆可租赁状态。

2.3 非功能需求

  1. 安全需求：密码必须哈希存储，接口必须经过 JWT 鉴权，管理接口必须校验角色权限。
  2. 一致性需求：租车、还车和维护状态变更必须保证订单状态和车辆状态同步。
  3. 国际化需求：核心菜单、按钮、表头、状态和公告内容应支持中英文切换。
  4. 可部署需求：系统应能通过 npm 安装依赖、初始化 MySQL 数据库并启动前后端服务。

3 系统概述

3.1 系统定位

系统定位为校园共享单车租赁和运营管理软件。学生端服务于租赁使用，后台端服务于运营管理，运维端服务于车辆维护，数据层服务于用户、车辆、站点、订单、维护和公告的持久化管理。

4 总体设计

4.1 前后端分离架构设计

系统采用前后端分离架构。H5 前端负责页面展示、移动端适配、语言切换、表单输入和用户交互；Node.js 后端负责认证、权限、业务规则、统一响应、异常处理、事务和数据库访问；MySQL 负责保存持久化数据。总体设计的重点是把页面展示和业务规则分离，让租车还车等关键逻辑集中在后端执行。

图4-1 系统总体架构图

图示说明：该架构图说明前端、后端和数据库的整体分层。前端层包含路由、页面、接口封装、国际化和登录状态管理；后端层包含 JWT 鉴权、角色权限、认证接口、车辆站点接口、订单租还接口、维护公告统计接口和统一响应；数据库层保存用户、车辆、站点、订单、维护记录和公告。该图的重点是说明系统不是静态 H5 页面，而是由前端页面、REST API 和数据库共同组成，核心业务通过后端接口和数据库事务保证一致性。

4.2 部署结构设计

前端构建产物部署在 Web 前端运行环境中，用户通过移动端浏览器访问；后端运行于 Node.js 服务环境中，向前端提供 RESTful API；MySQL 数据库作为独立数据服务。环境变量中包含端口、JWT 密钥和数据库连接配置，材料中均已脱敏。

图4-2 系统部署图

图示说明：该部署图说明软件实际运行时的节点关系。用户移动端浏览器加载 H5 页面，H5 页面访问前端构建产物并通过 REST JSON 调用 Node.js 后端服务，后端再通过 mysql2 访问 MySQL 数据库。该图的重点是明确浏览器、前端静态资源、后端业务服务和数据库服务的职责边界，也说明数据库连接信息、接口地址和主机信息需要通过环境变量配置并在材料中脱敏。

5 详细设计

5.1 用户认证与权限控制

认证模块由注册、登录、个人资料、密码修改和 JWT 校验组成。注册时写入学生账号，登录时后端根据 username 查询 users 表并使用 bcryptjs 比对密码哈希，成功后签发 JWT。前端将 token 保存到 localStorage，并在请求头中携带 Authorization。后端 auth 中间件负责解析 token，role 中间件根据 student、admin、staff 控制访问范围。该设计保证学生不能访问全局用户管理接口，运维人员只能访问维护相关接口，管理员可进入后台全局管理。

5.2 租车还车核心流程

租车流程先检查用户是否已有 renting 订单，再锁定车辆记录并判断 bikes.status 是否为 available。满足条件后，后端写入 rental_orders，生成订单编号，记录 start_time、hourly_rate、start_station_id，并把车辆状态改为 rented。还车流程锁定订单，判断订单是否属于当前用户或管理员，计算租赁分钟数并向上取整到小时，写入 duration_hours 和 total_amount，最后将订单状态改为 completed 并恢复车辆为 available。

图5-1 租车还车时序图

图示说明：该时序图展示学生端、H5 前端、订单接口、JWT 鉴权和 MySQL 数据库之间的调用顺序。租车阶段重点是身份校验、车辆锁定、订单写入和车辆状态占用；还车阶段重点是订单归属校验、时长计算、费用结算、订单完成和车辆释放。该图用于证明系统核心交易流程具备明确的前后端调用链和数据库事务边界，不依赖前端直接修改业务数据。

5.3 车辆、订单与维护状态

车辆状态包含 available、rented、maintenance 和 disabled。订单状态包含 renting、completed 和 cancelled。维护状态包含 processing 和 finished。系统通过状态枚举限制业务动作，例如只有 available 车辆可以租赁，只有 renting 订单可以归还，maintenance 车辆不会作为正常可租车辆参与租赁。

图5-2 订单与车辆状态图

图示说明：该状态图说明订单状态和车辆状态如何联动。学生租赁后车辆由可租赁转为已租赁，订单进入租赁中；学生归还后订单完成，车辆恢复可租赁；运维创建维护记录后车辆进入维护中，维护完成后恢复可租赁；管理员可以停用异常车辆。该图的重点是说明系统通过状态机控制业务可执行条件，避免维护中或停用车辆继续被学生租用。

5.4 国际化详细设计

前端通过 i18n 资源保存中文和英文菜单、按钮、状态、表头和提示文案，用户选择语言后写入 localStorage。公告表同时保存 title_zh、title_en、content_zh 和 content_en，前端根据当前语言展示对应内容。中英文切换不仅影响导航和按钮，也影响后台表头、状态文本和公告内容，保证学生和留学生都能理解主要业务页面。

6 数据库设计

6.1 数据库总体说明

数据库名称为 student_bike_rental，采用 MySQL 保存业务数据。数据库脚本位于 backend/sql/schema.sql 和 backend/sql/seed.sql，演示数据脚本位于 backend/src/utils/seedDemoData.js。数据库模型围绕用户、站点、车辆、租赁订单、维护记录和公告六类对象设计，通过外键、唯一约束和状态枚举保证业务数据可追溯、可校验。

6.2 数据对象关系

图6-1 数据对象关系图

图示说明：该 ER 图说明六张核心表之间的关系。users 表是用户、学生、管理员和运维人员的统一身份来源；stations 表与 bikes 表形成站点到车辆的一对多关系；bikes 表与 rental_orders 表形成车辆到租赁订单的一对多关系；maintenance_records 记录车辆和维护人员之间的处理关系；announcements 记录公告发布人与公告内容。该图重点说明数据库不是孤立表集合，而是围绕校园车辆租赁全过程建立关联。

6.4 数据初始化与约束说明

schema.sql 创建数据库和核心表；seed.sql 写入基础站点、车辆和公告；seedDemoData.js 写入多角色用户、多车型车辆、维护记录和历史订单。users.username、bikes.bike_no、rental_orders.order_no 采用唯一约束；rental_orders 的 user_id 和 status 建立组合索引，用于快速检查当前用户是否已有租赁中订单。租车和还车接口使用事务，防止订单写入成功但车辆状态未更新，或车辆恢复但订单金额未写入的问题。

7 接口设计

7.1 接口模块划分

系统接口以 /api 为统一前缀，包含 /api/auth、/api/users、/api/bikes、/api/stations、/api/orders、/api/maintenance、/api/announcements 和 /api/dashboard 等模块。所有接口统一返回 code、message、data 结构，错误由统一异常处理中间件处理。

7.2 核心接口说明

认证接口负责注册、登录、个人信息和密码修改；车辆接口负责车辆列表、详情、新增、编辑和停用；站点接口负责校园站点维护；订单接口负责我的订单、当前订单、租车和还车；维护接口负责维护记录查询、创建和完成；公告接口负责公告列表、详情、发布、编辑和隐藏；统计接口负责管理员仪表盘数据。租赁接口 POST /api/orders/rent 和归还接口 PUT /api/orders/:id/return 是系统核心业务接口。

9 运行与部署设计

后端通过 .env 读取服务端口、JWT 密钥和数据库配置，文档中连接地址和密钥已脱敏。初始化数据库时执行 schema.sql 创建表结构，再执行 seed.sql 和 seed:demo 脚本写入测试数据。前端使用 Vite 启动开发服务，也可以通过 npm run build 生成静态构建产物部署到 Web 服务中。

10 安全与权限设计

系统采用 JWT 保持登录状态，服务端通过 auth 中间件验证 token，通过 role 中间件限制角色访问。密码在写入数据库前进行哈希处理。数据库访问使用 mysql2 参数化查询，租赁和归还等关键操作使用事务避免状态不一致。软著材料中的数据库主机、密钥、接口访问地址、账号联系信息等均已脱敏。

11 测试与验证

本次验证完成了数据库初始化、演示数据写入、学生登录、车辆列表查询、租车、当前订单查询、还车、历史订单查询、管理员登录、统计接口和用户列表接口。前端通过浏览器完成学生登录、车辆详情、租赁确认、归还确认、中英文切换和后台页面访问验证。前端生产构建通过，后端入口模块加载通过，核心链路可运行。

12 结论

国际化学生单车租赁管理软件V1.0 已实现学生端租赁闭环、管理员后台管理、运维维护记录、公告发布、中英文界面展示、数据库持久化和可部署运行能力，具备校园学生单车租赁软件的主要功能。
